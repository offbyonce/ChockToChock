# 0010: Web build layout and tooling

Date: 2026-11-10. Status: accepted. Follows [0009](0009-web-first-delivery.md).

## Context
Decision 0009 makes Phase 2 a hosted web app with the Rust core running as WebAssembly. Today the
interface lives in `apps/desktop/ui`, the shared bindings call Tauri directly, and `AppError` and
`AppInfo` are defined in the Tauri shell. This record sets the layout and build tools for Phase 2,
step by step in the Phase 2 brief. The moves themselves happen in step 4.

## Decision

**Layout:**

| Path | What it is |
| --- | --- |
| `apps/web` | `@chocktochock/web`: page, entry, web host adapter, manifest, service worker, icons. Builds the site into `apps/web/dist`. |
| `packages/ui` | `@chocktochock/ui`: the shared Svelte interface (from `apps/desktop/ui/src`). Knows only a host interface, never Tauri or the browser directly. |
| `packages/bindings` | Types generated by ts-rs, plus `isAppError`. The Tauri `invoke` wrappers move to `apps/desktop`, so shared code no longer depends on `@tauri-apps/api`. |
| `crates/app-core` | Host-agnostic app operations: load a flattened pack, session actions, the versioned saved-progress export format, reading a 3.0 export, and `AppError` and `AppInfo` (moved from the Tauri shell). |
| `crates/web-host` | Thin `wasm-bindgen` glue over `app-core` and `simbrief`, as the Tauri shell is for desktop. |
| `apps/desktop`, `crates/store` | Parked (below). |

**Host interface.** `packages/ui/src/host.ts` defines what the interface needs from its host: core
calls, saved-progress storage, saving and opening a file, and fetching a SimBrief plan. It is
passed in through Svelte context at mount. The web app implements it with the WebAssembly module
and browser APIs; a desktop build would implement it with Tauri commands.

**Tooling:**

- **WebAssembly build:** `cargo build --target wasm32-unknown-unknown` for `web-host`, then the
  `wasm-bindgen` CLI with `--target web`, from a `just` recipe. Not wasm-pack. The CLI version
  must equal the `wasm-bindgen` crate version; both are pinned and bumped together.
- **Data across the boundary:** JSON strings, serialized with serde_json on the Rust side and
  parsed in the TypeScript wrapper against the ts-rs types. No serde-wasm-bindgen.
- **Saved progress:** `localStorage` behind the host adapter, under one versioned key.
- **Packs:** `pack build` writes one flattened `<id>.json` per aircraft. The site fetches it from
  its own address; it is not embedded in the WebAssembly module.
- **Site path:** Vite `base: "./"`, so the site works under the Pages project path, locally and in
  forks.
- **Tests:** app logic in `app-core` with nextest; Vitest for `packages/ui` and `apps/web`; one
  Node smoke test that loads the built WebAssembly module. No wasm-bindgen-test or browser runner
  for now. Offline, install and update checks are manual (brief steps 6 and 11).

**Service worker** (hand-written, no Workbox):

- The cache name is derived from the build hash, so each deploy gets its own cache and the old one
  is deleted once the new version takes over.
- A small Vite build hook writes the list of files to precache.
- **Never swap mid-session, offer reload.** A new version is downloaded in the background but
  never takes over an open session. The app shows "A new version is ready" with a Reload button;
  the new version runs only after the pilot reloads, or on the next launch.
- Brief step 6 includes a manual test of updating from one deployed version to the next: open the
  installed app on version A, deploy version B, confirm A keeps running unchanged with the reload
  offer shown, reload, confirm B runs, and confirm A's cache is gone.

**Parked:** `apps/desktop/src-tauri` and `crates/store` leave the workspace `members` for Phase 2.
Their files stay, each with a short "parked" note, and their dependency versions stay pinned in
the root `Cargo.toml` for a later desktop build (0009, later options).

**New dependencies and tools:** the `wasm-bindgen` crate (MIT or Apache-2.0), in `web-host` only;
the `wasm-bindgen` CLI at the same version; the `wasm32-unknown-unknown` target, added to
`rust-toolchain.toml`. No new JavaScript dependencies. `@tauri-apps/api` and `@tauri-apps/cli`
leave the pnpm catalog while desktop is parked.

## Consequences
- Parking the Tauri shell removes glib 0.18 from the dependency tree; it came only from Tauri's
  GTK stack. The `RUSTSEC-2024-0429` ignore in `deny.toml` is removed in step 4 (approved by the
  maintainer). Parking `store` also removes `rusqlite` and its bundled SQLite build.
- CI no longer needs the Linux WebKit libraries, but needs the `wasm-bindgen` CLI.
- Reviving desktop means returning both crates to the workspace, implementing the Tauri host, and
  restoring the CI step below.

## CI workflow changes (maintainer)
These change `.github/workflows/ci.yml` and are made by the maintainer when step 4 lands. The
version shown must match the `wasm-bindgen` crate version that step 4 pins.

Add the `wasm-bindgen` CLI to the existing install step:

```yaml
      - uses: taiki-e/install-action@v2
        with:
          tool: just,cargo-nextest,cargo-deny,wasm-bindgen@0.2.130
```

Remove the Linux WebKit step:

```yaml
      - name: Linux libraries for Tauri
        if: runner.os == 'Linux'
        run: |
          sudo apt-get update
          sudo apt-get install -y libwebkit2gtk-4.1-dev build-essential file libxdo-dev \
            libssl-dev libayatana-appindicator3-dev librsvg2-dev
```

The `wasm32-unknown-unknown` target needs no workflow change: the existing "Rust (version from
rust-toolchain.toml)" step installs it from `rust-toolchain.toml`.
